# racit_shedule — генератор розкладу коледжу

Веб-застосунок (Flask), який будує тижневий розклад (чисельник + знаменник)
з навантаження груп і експортує його в Excel.

## Запуск

### Docker

```bash
docker compose up --build
```

Відкрити http://localhost:8000 (інший порт: `PORT=8123 docker compose up --build`).
Результати зберігаються у volume `schedule-data`.

### Локально

```bash
python -m venv .venv
.venv\Scripts\activate          # Windows (Linux/macOS: source .venv/bin/activate)
pip install -r requirements-dev.txt
flask --app app run --debug
```

### Командний рядок (без веб-інтерфейсу)

```bash
python -m app.scheduler.cli "info/Розклад на 2026 р (інформація).xlsx" -o розклад.xlsx --time 120     --start 2026-09-01 --end 2026-12-31 --date 2026-09-26   # --date — ще й файл на дату
```

### Тести

```bash
pytest
```

## Вхідний файл

Excel з аркушами:

- **Навантаження** — колонки `Група | Дисципліна | Викладач | Кількість пар на тиждень | Зміна`.
  Кілька викладачів в одній клітинці (через перенос рядка) — це підгрупи: заняття
  проходить одночасно, зайняті обидва викладачі й дві аудиторії.
- **аудиторії** — номер/назва аудиторії та примітка («Комп'ютер», «Тільки для програмістів»,
  «У крайніх випадках», «Тільки лабораторні у хт»…).

Приклад: `info/Розклад на 2026 р (інформація).xlsx`.

## Як будується розклад

Модель у `app/scheduler/solver.py` розв'язується [OR-Tools CP-SAT](https://developers.google.com/optimization/cp/cp_solver)
— стандартний інструмент для задач розкладу.

**Жорсткі правила** (ніколи не порушуються):

- викладач не веде два заняття одночасно; у викладача не більше 4 пар на день;
- у групи не більше одного заняття в пару і лише в межах своєї зміни
  (І зміна — пари 1–4, ІІ зміна — пари 5–7; пар максимум 7). Одна пара сусідньої
  зміни (5-та для І, 4-та для ІІ) дозволена як небажаний «перехід між змінами» —
  коли без неї не вміститься навантаження викладача (напр. 17–19 пар лише в ІІ зміні
  при 15 місцях) — і показується попередженням;
- кількість пар кожної дисципліни точно відповідає навантаженню. Дробове навантаження
  чергується по тижнях (1,5 → 1 / 2 / 1 / 2…). Як у шаблоні коледжу, дві «половинки»
  ділять одну пару (Математика в чисельнику / Біологія в знаменнику), тож обидва тижні
  рівні за кількістю пар;
- в один день у групи немає двох однакових дисциплін (якщо пар дисципліни за тиждень
  більше, ніж днів, — це м'яке правило);
- одночасних занять (крім фізкультури) не більше, ніж аудиторій.

**М'які правила** (штрафи, у порядку пріоритету з `info`):

1. навчальний день групи — 3–4 пари без «вікон», без вільних днів;
2. без «вікон» у викладачів;
3. рівномірне навантаження викладачів по днях;
4. однакова «форма» дня в чисельнику і знаменнику;
5. комп'ютерних занять одночасно не більше, ніж комп'ютерних класів;
6. заняття починаються з першої пари зміни.

Пошук іде у два етапи: спершу розклад, ідеальний за правилами груп (зазвичай 15–20 с),
потім — не погіршуючи його — покращення для викладачів. Рекомендований час — 120 с і більше.
Розбивка штрафу та показники якості — на сторінці результату й на аркуші «Перевірка».

**Семестр і суботи.** Генерується розклад пн–пт на два тижні (чисельник/знаменник).
Календар (`semester.py`) задається датами семестру у формі:

- тиждень, у який починається семестр, — чисельник (можна змінити), далі по черзі;
- субота повторює будній день за ротацією: перша субота — за понеділком, наступна —
  за вівторком, … п'ятницею, далі знову з понеділка; пари — того тижня, до якого належить
  субота. Перевірено на файлах з `info/`: 26.09.2026 — субота за четвергом, знаменник.

На сторінці результату можна обрати дату й побачити або завантажити розклад саме на неї
(як щоденні файли «Розклад на 29_09_2026 (Вівторок)»); список субот — там само і на аркуші
«Суботи» в Excel.

Викладачі, записані як «Ім'я ПРІЗВИЩЕ» (напр. «Сергій ПАНДРАК»), зводяться до
«Прізвище І. Б.» за навантаженням та аркушем «Викладачі» (якщо він є у файлі).

Аудиторії (`rooms.py`): фізкультура — спортзал, «Захист України» — тир, комп'ютерні
дисципліни — комп'ютерні класи (КН/ІПЗ — також аудиторії програмістів), решта — звичайні,
у крайньому разі резервні. Алгоритм «свій кабінет»: викладачі від найзавантаженіших,
кожному — аудиторія, вільна в більшості його пар (у середньому ~1,8 аудиторії на викладача).

Готовий розклад перевіряється незалежним валідатором (`validator.py`).

## Excel

- **Розклад** — усі групи; кожна пара — два рядки (верх — чисельник, низ — знаменник),
  однакові заняття об'єднані;
- **1–4 курс** — те саме по курсах;
- **Викладачі** — зайнятість кожного викладача;
- **Навантаження** — план vs поставлено по тижнях;
- **Суботи** — дата, тиждень і за розкладом якого дня навчаються;
- **Перевірка** — порушення правил, показники якості, розбивка штрафу.

Аркуші налаштовані для друку (A3, альбомна, по ширині сторінки); на аркушах курсів
приховано пари, яких у цих груп не буває (друга зміна для 1 курсу тощо).

## Структура

```
app/
  __init__.py        Flask app factory
  routes.py          сторінки
  jobs.py            фонові задачі генерації (data/jobs/<id>/)
  scheduler/
    loader.py        читання xlsx
    solver.py        CP-SAT модель
    rooms.py         призначення аудиторій
    metrics.py       показники якості
    semester.py      календар: чисельник/знаменник, суботи за ротацією
    validator.py     перевірка правил
    exporter.py      експорт в Excel
    cli.py           запуск з консолі
tests/
```
